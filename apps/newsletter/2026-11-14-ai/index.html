최신 AI 소식

Gemini 4 Carbon과 역할을 나눈 에이전트

Google은 11월 10일 Gemini 4 Carbon을 개발자와 기업 등에 제공한다고 발표했습니다. 공식 발표에서 강조하는 분야는 복잡한 소프트웨어 작업, 장시간 수행하는 에이전트 작업, 과학적 추론입니다. Antigravity에서는 하나의 요청을 여러 에이전트의 작업으로 나누는 /swarm을 프리뷰로 소개했습니다. 설계·조정·감사처럼 깊은 추론이 필요한 역할과, 병렬 실행할 수 있는 역할을 구분하고 변경 사항을 검사하는 검증자를 두는 방식입니다. Google 공식 발표

이 발표를 개발자 관점에서 읽으면 새 모델의 순위보다 작업 분해와 검증 구조가 제품의 일부가 되고 있다는 점이 중요합니다. 예를 들어 모델 분석 도구를 개선한다면 한 작업자는 파서를 고치고, 다른 작업자는 화면을 구현하며, 별도 작업자는 지원하지 않는 연산과 잘못된 입력을 찾아낼 수 있습니다. 서로 독립적인 작업은 동시에 진행하고, 서로 맞물리는 인터페이스는 먼저 합의하는 식입니다.

다만 작업자 수가 늘었다고 실패 확률이 자동으로 낮아지지는 않습니다. 세 작업자가 모두 같은 잘못된 스키마를 읽었다면 결과가 서로 일치해도 틀릴 수 있습니다. 구현자와 검증자가 같은 예제만 보고 같은 가정을 공유하면 검증자는 사실상 구현자의 설명을 다시 확인하는 역할에 머뭅니다.

따라서 도입 실험에서는 다음 세 가지를 분리해 측정하는 편이 좋겠습니다.

  • 완료율: 프로그램이 실행되는지를 넘어, 미리 정한 요구사항을 모두 만족했는가.

  • 총비용: 최초 생성뿐 아니라 실패한 시도, 재시도, 검증 호출에 들어간 비용까지 얼마인가.

  • 사람의 개입: 사용자가 원인을 설명하거나 결과를 다시 손봐야 했던 횟수는 몇 번인가.

제조사의 발표는 어떤 기능을 제공하려는지 보여 줍니다. 그러나 자신이 관리하는 저장소에서 생산성이 얼마나 좋아지는지는 별도의 실험 문제입니다. 작은 버그 수정 하나를 단일 에이전트와 역할 분담 방식에 각각 맡기고, 같은 테스트와 시간 제한으로 비교하는 것이 출발점이 될 수 있습니다.

개별 작업의 병렬화와 여러 모델의 같은 대답은 다르다

가령 분석할 파일 12개를 작업자 세 명에게 네 개씩 맡기면 조사 시간은 줄일 수 있습니다. 반면 세 작업자가 같은 질문에 답하고 다수표만 취하는 실험은 정보가 늘었는지 판단하기 어렵습니다. 원자료를 달리 읽더라도, 세 명 모두 하나의 잘못된 요구사항을 그대로 가정하면 결과는 같은 방향으로 어긋납니다. 앞의 경우에는 파일의 담당·누락 여부를, 뒤의 경우에는 같은 결론에 이른 근거가 얼마나 겹치는지 따로 확인해야 합니다.

가상의 개발 과제에서 한 작업자는 20분, 병렬 구현팀은 12분 걸렸지만 통합 검증에 10분이 더 들었다고 합시다. 팀 방식의 구현 자체는 빨라도 사용자에게 전달할 때까지는 22분입니다. 이 차이를 기록하면 추가 작업자를 또 넣을지, 먼저 인터페이스의 변경 비용을 줄일지 선택할 수 있습니다.

주목할 만한 논문

Physics2Weight가 실제로 생성하는 것

NTT 연구진의 Physics2Weight는 11월 7일 공개된 프리프린트입니다. 지배방정식과 초기·경계조건을 LLM에 전달하고, 신경망 구조와 수치 가중치를 생성하게 합니다. 이후 외부 평가기가 물리 법칙 위반 정도를 계산해 피드백합니다. 초기 구조 편집과 달리, 반복 보정 단계에서는 구조를 고정하고 가중치만 바꿉니다. 논문 본문 4절

실험 대상은 열·이류·Burgers·Allen–Cahn 방정식 네 종류입니다. 가중치 보정은 다섯 차례이며, 초기 결과를 포함한 여섯 후보에서 최종 결과를 선택합니다. 저자들은 비교한 PINN과 WSP보다 낮은 해 오차를 보고하지만, 비선형 문제에서는 해 오차 개선이 PDE 잔차 개선으로 이어지지 않았다고 설명합니다. 이는 저자들의 해당 실험 결과이지 모든 PDE에 대한 우월성은 아닙니다. 실험 설정과 결과

여기서 구조 편집은 중요합니다. 논문은 지수 감쇠나 좌표변환 같은 수학적 연산을 계산 과정에 넣을 수 있도록 합니다. 따라서 결과를 “숫자 몇 개만으로 물리학을 배웠다”라고 읽으면 의미가 달라집니다. 지식을 구조에 넣는 효과와 가중치를 생성하는 효과를 함께 평가해야 하는 접근입니다. 구조 편집 방식

해가 비슷한 것과 법칙을 만족하는 것은 다르다

이 차이를 이해하기 위한 간단한 사고실험을 해보겠습니다. 실제 해에 아주 작은 진폭의 고주파 진동을 더한 예측이 있다고 가정합니다.

u^(x)=u(x)+εsin⁡(kx)\widehat{u}(x)=u(x)+\varepsilon\sin(kx)

예측값 자체의 차이는 최대 ε입니다. 그래프를 멀리서 보면 거의 겹칠 수 있습니다. 그런데 이 차이를 공간에 대해 두 번 미분하면 다음과 같습니다.

d2dx2(u^(x)−u(x))=−εk2sin⁡(kx)\frac{d^2}{dx^2}\bigl(\widehat{u}(x)-u(x)\bigr) =-\varepsilon k^2\sin(kx)

진동수가 커지면 미분 오차는 k의 제곱에 비례해 커집니다. 이 예는 논문의 특정 실험을 재현한 것이 아니라, 작은 함수값 오차가 작은 미분 오차를 보장하지 않는다는 점을 보여 주는 수학적 예시입니다. 미분항이 들어가는 물리 방정식에서는 예측 곡선이 그럴듯해 보이는 것만으로 충분하지 않은 이유입니다.

따라서 물리 모델의 평가표에는 해 오차뿐 아니라 방정식 잔차, 초기조건 위반, 경계조건 위반이 따로 있어야 합니다. 한 점수로 합치더라도 원래 항목을 남겨야 어떤 성질을 희생해 점수를 얻었는지 알 수 있습니다. 표본점을 촘촘하게 바꾸거나 경계 부근을 별도로 평가하는 것도 유용한 검증 설계입니다.

검증점에 맞은 후보가 전체 구간에서도 맞는가

간단한 수치 예를 만들어 봅시다. 공간 구간을 길이 1로 놓고 0.1 간격으로만 평가하면, 진폭 0.001인 사인파에 파수 20π를 넣었을 때 모든 격자점에서 추가 진동은 0입니다. 하지만 격자 사이에서 값이 흔들리며, 두 번 미분한 항의 최대 크기는 약 3.95입니다. 여기서 문제는 사인파가 유난히 어려워서가 아니라, 같은 격자가 후보 생성과 최종 점검에 동시에 쓰인 상황입니다. 입력 간격을 조금 옮기고, 초기·경계 주변을 별도로 빽빽하게 보는 이유입니다.

논문의 여섯 후보 중 하나를 고르는 과정도 이 원리와 연결됩니다. 후보 선택에 쓰인 잔차 평가와 최종 보고에 쓸 평가점을 분리하면, 선택기가 적은 표본의 우연한 오차를 쫓았는지 볼 수 있습니다. 해를 모르는 경우에는 보존량이나 경계조건을 독립 기준으로 남길 수 있지만, 이를 만족했다고 고유해에 가까워졌다고 바로 결론 내려서는 안 됩니다. Physics2Weight의 설정과 결과

오늘의 AI 개념

Weight Space Programming

일반적인 학습에서는 손실함수와 최적화 알고리즘이 가중치를 갱신합니다. Weight Space Programming에서는 작업 설명을 읽은 LLM이 사용할 가중치를 직접 출력합니다. Physics2Weight처럼 평가 결과를 받아 다시 출력하는 반복도 가능합니다. 이때 “역전파 없이 만든다”는 표현은 목표 신경망의 제작 절차에 관한 말입니다. 이미 학습된 LLM을 사용한다는 사실이나 생성·평가 비용이 사라진다는 뜻은 아닙니다. Physics2Weight의 WSP 정의

가중치를 프로그램처럼 생각하려면 작은 예가 도움이 됩니다. 두 입력의 차이가 양수인지를 판단하는 규칙을 만들고 싶다고 해보겠습니다. 선형 점수 s = x1 - x2는 가중치 [1, -1]과 편향 0으로 표현할 수 있습니다. 이 숫자는 데이터에서 배운 결과가 아니라, 이미 알고 있는 규칙을 신경망의 표현 형식으로 옮긴 것입니다.

복잡한 네트워크에서 이런 변환이 자동으로 이루어진다면 흥미로운 도구가 됩니다. 다만 “신경망 형태로 저장했다”와 “데이터에서 새로운 규칙을 발견했다”는 서로 다른 성과입니다. 전자는 배포 형식의 통일이나 기존 추론 엔진 활용에 가치가 있을 수 있고, 후자는 일반화 성능으로 평가해야 합니다.

재현 연구가 던진 질문

Alan Turing Institute의 초기 재현 연구는 작은 네트워크의 가중치 생성 능력을 확인하면서도, 결과를 프로그램의 변환으로 해석할 필요가 있다고 주장합니다. 연구진은 생성된 Breakout 네트워크를 Python으로 역변환했고, 검사한 49,189개 상태에서 같은 행동을 선택했다고 보고했습니다. 반면 손글씨 분류에서는 생성 네트워크의 평균 성능이 약 50%로, 데이터를 사용한 간단한 템플릿 분류기의 82%보다 낮았습니다. 재현 연구 요약

이 결과는 가중치 생성이 무의미하다는 결론이 아닙니다. 무엇이 새로워졌는지를 더 정밀하게 구분하자는 근거입니다. 규칙을 찾아내는 능력, 그 규칙을 코드로 쓰는 능력, 같은 규칙을 신경망 가중치로 표현하는 능력은 각각 별도로 시험할 수 있습니다.

가중치, 구조, 생성 비용을 따로 적기

가중치 9,000개를 FP32로만 저장하면 36,000바이트입니다. 그러나 각 값을 소수 문자열 10자와 구분 문자 1자로 내보낸다면 값 목록만 약 99,000문자입니다. 모델 구조와 이름까지 JSON으로 쓰면 더 길어집니다. 매 단계에서 목록 전체를 다시 생성하는 경우에는 최종 파일 크기와 제작 중 출력량이 크게 달라집니다. 생성기가 어떤 숫자를 잘 만들었는지를 보려면 최종 산출물 외에 비정상 값, 자리수 손실, 구조에 쓰이는 부가 연산도 기록해야 합니다.

연구와 개발에 적용한다면

동일한 규칙을 세 가지 방식으로 비교하기

작은 제어기나 점수 함수를 대상으로 실험한다면 다음 세 가지 후보를 같은 조건에서 비교하는 설계를 권합니다.

  1. LLM이 직접 작성한 Python 함수

  2. LLM이 생성한 신경망과 가중치

  3. 동일한 입력·출력 정의로 실제 학습한 작은 신경망

세 후보에 제공한 정보를 같게 하고, 테스트 입력은 생성 전에 분리합니다. 평가에는 정답률이나 보상뿐 아니라 추론 시간, 메모리, 실패 사례, 제작 비용을 포함합니다. 이렇게 해야 성능 차이가 가중치 표현에서 오는지, 더 좋은 규칙이나 더 많은 정보에서 오는지 구분하기 쉬워집니다.

구조 지식이 만든 이득을 분해하는 네 칸

같은 문제를 구조 변경 허용 여부와 가중치 생성 방식이라는 두 축으로 나누면 네 조건이 됩니다. 수식 기반 구조를 고정한 상태에서도 직접 생성이 무작위 초기화보다 이점이 있는지 먼저 봅니다. 반대로 생성 방법을 고정하고 수식 연산을 구조에 추가했을 때의 개선도 따로 비교합니다. 이런 교차 설계를 하면 가중치와 구조 사이의 상호작용까지 볼 수 있습니다. 예를 들어 특수 구조가 있을 때만 직접 생성이 잘 된다면, 일반 신경망 가중치를 더 잘 만든다는 주장과는 증거의 범위가 달라집니다.

반복 생성 방식과 비교 대상의 계산 예산도 고정해야 합니다. 예를 들어 동일한 평가기를 여섯 번 질의해서 최선의 한 개를 고르는 방법을, 평가 한 번만 받은 모델과 비교하면 결과 차이는 구조나 가중치 생성이 아니라 선택 기회에서 올 수도 있습니다. 후보 수와 최종 선택 규칙을 함께 맞추거나, 성능을 평가기 호출량의 함수로 제시하는 편이 공정합니다.

오늘의 결론

오늘의 두 흐름은 같은 문제로 만납니다. 에이전트가 많아져도, 신경망을 더 쉽게 만들어도, 결과를 믿을 근거는 별도로 설계해야 합니다. 앞으로 주목할 것은 생성 속도만이 아니라 실패를 드러내는 평가기, 비교 가능한 실험, 그리고 결과를 다시 실행할 수 있는 기록입니다.

다음 실험의 질문도 이렇게 좁혀볼 수 있습니다. “LLM이 신경망을 만들 수 있는가?”보다 “같은 명세에서 코드보다 신경망 가중치로 만드는 편이 어떤 조건에서 더 유용한가?” 이 질문이 더 작지만, 답을 얻으면 실제 도구 설계로 이어질 수 있습니다.
